# 04 · 내용 뼈대와 서사 설계

이 페이지는 연출보다 **내용의 구조**가 먼저다. 연출은 그 구조를 따라 붙인 것이라,
자기 주제로 바꿀 때도 이 뼈대부터 다시 짜야 한다.

## 1. 페이지가 가르치는 개념 체계

아래는 페이지의 주장을 정리한 것이다(원문 인용이 아니라 요약).

```
한 편의 콘텐츠
├─ WHO   누가 말하는가
├─ WHAT  무엇을 말하는가 ──→ 대본
└─ HOW   어떻게 보여주는가 ─→ 포맷 ─┐
                                    ├─→ 구조(시간 순서)
                          대본 ─────┘     ├─ 훅    ─ 비주얼 훅 / 텍스트 훅 / 스포큰 훅
                                          ├─ 빌드
                                          ├─ (반전)
                                          ├─ 보상
                                          └─ CTA
재료(모든 구간에 공통)
├─ A롤    화자로서 말하는 장면
├─ B롤    그 외 모든 시각 자료 ─ 일상 / 연출 / 창의적
├─ 텍스트  제목 · 자막 · 화면 문구
└─ 소리    직접 말하기 / 보이스오버
```

| 축 | 분류 | 구분 기준 |
|---|---|---|
| 포맷 | 스토리텔링 · 정보전달 · 챌린지 | **시청자가 무엇을 기다리는가** (이 사람은 어떻게 될까 / 어떻게 이해할까 / 해낼 수 있을까) |
| 구조 | 훅 → 빌드 → 보상 → CTA | 시간 위의 역할 |
| 훅 | 비주얼 · 텍스트 · 스포큰 | 주의를 붙잡는 통로. 같은 순간에 겹쳐 작동한다 |
| 화면 | A롤 · B롤 | 화면 속 인물이 **화자인가 자료인가**. 말하는 모습이어도 자료로 쓰이면 B롤 |
| B롤 | 일상 · 연출 · 창의적 | 실제 기록인가 / 일부러 찍었는가 / 비유로 바꿨는가 |
| 스토리 곡선 | 사건 → 기대 → 갈등 → 선택 → 변화 | 감정의 오르내림 |

포맷은 배타적이지 않고 결합된다(스토리텔링+챌린지 등). 레퍼런스 26편 중 14편이 복수 태그다.

**이 체계의 쓸모**는 페이지가 스스로 밝힌다: 분류의 목적은 **레퍼런스 수집**이다.
B롤을 세 종류로 나눌 수 있어야 종류별로 장면을 모아둘 수 있고,
"이거 스토리텔링이에요"에서 끝나지 않고 재료와 구조까지 같은 말로 설명할 수 있다.

## 2. 서사 설계 — 왜 이 순서인가

| 단계 | 섹션 | 독자에게 하는 일 |
|---|---|---|
| 붙잡기 | 히어로 | 실제 영상 한 편을 먼저 보여준다. 설명 전에 대상부터 |
| 정당화 | 서론 | 재즈·체스 비유로 "패턴은 창의의 반대가 아니다"를 납득시킨다 |
| 지도 | 개념 사다리 | 전체를 한 번에 보여준 뒤 한 단계씩 내려간다. 마지막에 다시 전체 |
| 확대 1 | 포맷 · 스토리 곡선 | 지도의 한 칸(포맷)을 키운다 |
| 확대 2 | 타임라인 | 지도의 다른 칸(구조)을 **실제 영상 한 편 위에** 올려 증명한다 |
| 확대 3 | 층 분해 · B롤 | 한 순간을 재료로 쪼갠다 |
| 변주 | 프로모션 · 경우의 수 · 실험실 | 같은 재료로 다른 결과가 나오는 것을 직접 눌러 보게 한다 |
| 통합 | 분석 문장 | 배운 용어를 한 문단에 전부 넣어 다시 읽힌다. 용어마다 앞 장면이 옆에 뜬다 |
| 적용 | 내 대본으로 · 결론 | "그래서 내 대본 한 문장에 무엇을 붙일까"로 좁힌다 |
| 자료 | 라이브러리 · 대본 100 | 근거 자료를 뒤에 붙인다. 본문 곳곳의 `↗` 버튼이 여기로 연결된다 |

눈여겨볼 장치.

- **전체 → 부분 → 전체**를 장면 안에서도, 페이지 전체에서도 반복한다(사다리·곡선·분석 문장 모두 끝에서 물러나 전체를 보여준다).
- **예시 한 편을 끝까지 끌고 간다.** 타임라인, 분석 문장의 옆 패널, "내 대본으로"의 참고 장면이 모두 같은 영상(21번)이다.
- **가상 사례 하나를 끝까지 끌고 간다.** 실험실 → 분석 문장 → 내 대본 타임라인이 전부 "회사를 그만두고 카페를 연다"는 같은 설정이다.
- **설명한 것을 자기 형식에 적용한다.** 문서 자체가 훅(히어로) → 빌드 → 보상(분석 문장) → CTA(내 대본에 붙여보라) 순서다.
- **본문과 자료를 잇는다.** 모든 개념 옆에 실제 사례 버튼이 있고, 누르면 해당 영상이(필요하면 해당 초부터) 열린다.

## 3. 대본 100편 통계

`scripts-100.csv` 기준. 100편 중 전사가 훼손된 5편을 뺀 **95편**(문맥 분석 73, 부분 분석 22)으로 계산했다.
구간 경계는 원 제작자가 문장 단위로 나눈 값이다.

### 길이

| 구분 | 값 |
|---|---|
| 전체 길이 중앙값 | 70.7초 (최소 20초 · 최대 178초) |
| 30초 미만 | 3편 |
| 30–60초 | 32편 |
| 60–90초 | 37편 |
| 90초 이상 | 23편 |

### 구간별

| 구간 | 있는 영상 | 길이 중앙값 | 사분위 범위 | 전체 대비 비중(중앙값) |
|---|---|---|---|---|
| 훅 | 95 / 95 | 8.4초 | 5.8–12.1초 | 13.6% |
| 빌드 | 95 / 95 | 38.3초 | 25.2–50.4초 | 53.7% |
| 트위스트 | 24 / 95 | 12.0초 | 7.3–17.9초 | 13.3% |
| 보상 | 80 / 95 | 12.8초 | 8.0–19.0초 | 20.0% |
| CTA | 55 / 95 | 5.2초 | 3.8–7.7초 | 8.6% |
| 아웃트로 | 34 / 95 | 3.6초 | 1.3–5.3초 | 3.3% |

### 순서

| 순서 | 편수 |
|---|---|
| 훅 → 빌드 → 보상 | 12 |
| 훅 → 빌드 → 보상 → CTA | 12 |
| 훅 → 빌드 → 보상 → CTA → 아웃트로 | 8 |
| 훅 → 빌드 → CTA | 5 |
| 훅 → 빌드 → 보상 → 빌드 → 보상 → CTA | 4 |
| 훅 → 빌드 → 보상 → 아웃트로 | 4 |

상위 세 가지가 전체의 34%이고 나머지는 변형이다. 빌드와 보상이 두 번 도는 형태도 흔하다.

### 읽을 수 있는 것

- **"대본상의 훅"은 3초가 아니라 8초 안팎이다.** 본문은 훅을 "처음 3초"라고 부르지만,
  문장 단위로 나눈 훅 구간의 중앙값은 8.4초다. 첫 3초는 화면·글자가 붙잡는 시간이고, 말로 하는 도입은 그보다 길다고 보면 맞는다.
- **절반 이상이 빌드다.** 한 편의 54%가 빌드에 쓰인다. 훅을 다듬는 것만큼 빌드에 무엇을 채울지가 분량상 더 큰 문제다.
- **CTA는 끝 10%에 온다.** 시작 위치 중앙값이 전체의 90% 지점이고, 중간(70% 이전)에 넣은 경우는 55편 중 8편이다.
- **CTA 유무와 좋아요는 차이가 없다.** 좋아요 중앙값이 CTA 있음 31,113 / 없음 32,661.
- **트위스트는 4편 중 1편.**

### 주의

- 표본이 치우쳐 있다. 14개 계정 중 **두 계정이 100편의 절반**(30편, 20편)을 차지한다. "잘 되는 릴스의 일반 법칙"이 아니라 "이 계정들의 습관"에 가깝다.
- 좋아요 상위만 모은 것이라 비교 대상(안 된 영상)이 없다. 무엇이 성과를 만들었는지는 이 자료로 말할 수 없다.
- 전사는 자동 인식이고 사람이 듣고 검수하지 않았다고 원본에 명시돼 있다. 구간 경계는 초 단위 정밀도를 기대하기 어렵다.

## 4. 레퍼런스 26편 요약

| 항목 | 값 |
|---|---|
| 태그 | 스토리텔링 25 · 정보전달 8 · 프로모션 6 · 챌린지 2 (복수 태그) |
| 길이 | 10–100초, 중앙값 54초 |
| 좋아요 | 3 – 966,294 (바이럴 영상과 직접 만든 영상이 섞여 있다) |
| 전개 분석 | 편당 2–5개 시점(대부분 4개) |
| A롤·B롤 구간 분류 | **1편(21번)에만** 있다 — 타임라인 장면의 재료 |
| 화면 문구 전사 | 4편 |

스토리텔링이 26편 중 25편이라 사실상 **스토리텔링 레퍼런스 모음**이고, 챌린지는 2편뿐이다.
구간 단위 A롤·B롤 분류는 손이 많이 가서 한 편만 해 두었다 — 자기 자료를 만들 때 가장 비용이 큰 부분이 여기다.

## 5. 자기 주제로 옮길 때의 틀

이 문서 형식은 숏폼이 아니어도 **"분류 체계 + 실제 사례"**로 설명할 수 있는 주제면 그대로 쓸 수 있다.

1. **축을 3–5개 정한다.** 각 축은 한 가지 질문으로 나뉘어야 한다(포맷 = 무엇을 기다리는가).
2. **축 사이의 관계를 트리로 그린다.** 이것이 사다리 장면이 된다. 6–10단계가 적당하다.
3. **끝까지 끌고 갈 사례 하나**와 **가상 예시 하나**를 정한다.
4. **축마다 맞는 장면 형식을 고른다.**

| 내용의 성격 | 맞는 형식 |
|---|---|
| 상하 관계, 파생 | 사다리(트리 + 카메라) |
| 대등한 유형 3–4개 | 가로 트랙 |
| 시간에 따른 변화 | 곡선 |
| 한 사례의 시간 구조 | 타임라인 |
| 동시에 겹치는 요소 | 층 분해 |
| 두 축의 조합 | 표 + 토글 실험실 |
| 요약·복습 | 단어 단위로 밝아지는 문단 |

5. **사례 자료를 같은 스키마로 모은다**([05](05-data-schema.md)). 본문의 모든 주장에 사례 버튼을 하나 이상 붙인다.
