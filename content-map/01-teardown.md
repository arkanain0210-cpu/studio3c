# 01 · 구조 분해

## 1. 정체

- **무엇**: 숏폼(릴스) 제작팀이 용어를 통일하려고 만든 내부 교육·레퍼런스 문서. 본문에 "앤써가", "앤써화" 같은 자기 지칭이 나온다.
- **공개 범위**: `<meta name="robots" content="noindex,nofollow">`. 검색에는 안 잡히지만 로그인 없이 URL만 알면 열린다.
- **출신**: 코드 주석과 오류 문구("HTML과 콘텐츠분석_개별렌더 폴더를 함께 보관해 주세요")로 보아
  원래 **로컬에서 여는 HTML 한 파일 + 영상 폴더**였고, 나중에 Railway에 올리면서 영상을 `/api/content-media/*`로 돌렸다.
- **원고**: 주석에 `정리.psd`, `콘텐츠분석.txt`가 반복해서 나온다. 포토샵으로 그린 개념도와 텍스트 메모를 웹으로 옮긴 것이다.

## 2. 기술 구성

| 층 | 내용 |
|---|---|
| 마크업 | `header.top` + `main > section × 17` + `dialog#playerDialog` |
| 스타일 | 한 덩어리 CSS(약 730개 규칙). CSS 변수 9개, 미디어쿼리 2단(900px, 759px) |
| 스크립트 | 바닐라 JS 748줄. 모듈·번들러·외부 라이브러리 없음 |
| 그래픽 | 전부 인라인 SVG를 JS로 생성(오선지, 체스판, 곡선, 타임라인 파형, 연결선) |
| 데이터 | 스크립트 맨 위 `const videos=[…]`(754KB) · `const S100=[…]`(316KB)로 박아 넣음 |
| 미디어 | `<video>` 11개(자동재생 2, 타임라인 모니터 1, 구간 반복 카드 7, 팝업 1) + 분석 장면 옆 패널에서 그때그때 생성 |
| 폰트 | Pretendard 400/500/600/700 woff2 자체 호스팅 |

**무게 분포**: 전체 1.9MB 중 로직은 4%뿐이다. 나머지는 데이터(전사 448개 큐 + base64 썸네일 26장 482KB)와
JS가 그려 넣은 SVG다. 즉 "가벼운 엔진 + 무거운 데이터" 구조이고, 엔진만 떼어 쓰기 쉽다.

## 3. 페이지 지도

`장면` = 화면에 고정된 채 스크롤로 진행되는 구간(`.scene`), `일반` = 평범하게 흘러가는 구간(`.plain`).
높이는 그 장면이 차지하는 스크롤 길이다.

| # | id | 종류 | 높이 | 라벨 | 화면에서 일어나는 일 |
|---|---|---|---|---|---|
| 1 | `home` | 장면 | 230vh | — | 가운데 세로 영상이 화면 전체로 커지고, 제목 두 줄이 좌우로 갈라져 나간 뒤 한 문장이 올라온다 |
| 2 | `intro` | 장면 | 440vh | 00 서론 | 세 문장이 단어 단위로 진해진다. 읽고 있는 문장에 맞춰 오른쪽 예시(오선지 → 체스판 → 패턴 칩)가 바뀐다 |
| 3 | `atlas` | 장면 | 1120vh | (01) | **개념 사다리.** 10단계에 걸쳐 노드가 내려오고 선이 그려지며 카메라가 따라 내려간다. 마지막에 전체 보기 |
| 4 | `formats` | 장면 | 460vh | 02 FORMAT | 세로 스크롤이 가로 이동이 된다. 패널 4장(스토리텔링·정보전달·챌린지·결합) |
| 5 | `story` | 장면 | 820vh | 03 STORYTELLING | 감정 곡선 5점을 카메라가 선 끝을 따라가며 그리고, 끝에서 물러나 전체를 보여준다 |
| 6 | `structure` | 장면(어두움) | 1000vh | 04 타임라인 | 실제 릴스 한 편(40.85초)을 편집 타임라인에 올린다. 재생선이 지나가면 오른쪽 모니터가 그 구간을 반복 재생 |
| 7 | `expression` | 장면 | 520vh | 05 EXPRESSION | 한 화면이 3D로 누우며 화면·음성·텍스트 세 층으로 벌어졌다 다시 합쳐진다 |
| 8 | `broll` | 일반 | — | 06 B-ROLL | 카드 3장. 올리면 지정 구간만 반복, 누르면 소리 |
| 9 | `promotion` | 일반 | — | 07 STORY → PRODUCT | 한 영상을 4구간(공감·필요·답·행동)으로 자른 카드 |
| 10 | `cases` | 일반 | — | 08 경우의 수 | 화면 구성 × 주제 표 + 무한 흐름 띠(마키) |
| 11 | `lab` | 일반(어두움) | — | 09 COMBINATION LAB | 포맷 토글 3개 → 조합 7가지 결과가 바뀌는 인터랙티브 예시 |
| 12 | `analysis` | 장면(어두움) | 1100vh | 10 | 긴 한 문단이 단어 단위로 밝아진다. 용어가 켜질 때마다 옆 패널에 앞 장면의 축소판이 뜬다 |
| 13 | `apply` | 일반 | — | 11 BACK TO YOUR SCRIPT | 3레인 미니 타임라인. 빈칸이 닦이듯 채워진다 |
| 14 | `conclusion` | 일반(어두움) | — | 12 결론 | 4단계 흐름 + 스크롤에 맞춰 밝아지는 큰 문장 |

| 16 | `scripts` | 일반 | — | 14 SCRIPTS 100 | 95줄 아코디언. 줄마다 구간 막대, 펼치면 구간별 원문과 판단 이유 |

상단 메뉴는 8개(`#atlas #formats #structure #expression #lab #conclusion #library #scripts`),
현재 위치는 `IntersectionObserver`로 표시한다.

## 4. 팝업(영상 플레이어)

`<dialog>` + `showModal()`. 왼쪽 영상, 오른쪽 읽기 영역 2탭.

- **전개 분석**: 태그, 기대 질문, 수치, 패턴 한 줄, "전개에서 가져올 것", 시점 버튼(누르면 그 초로 이동), A롤·B롤 구간(접힘), 검수 메모, 원본 링크
- **전사·번역**: 종류(음성/화면 문구) × 언어(한국어+원문/한국어/원문). 재생 위치에 해당하는 줄이 강조된다
- 좌우 화살표 키로 이전·다음, 닫으면 열기 전 포커스로 복귀, 배경 스크롤 잠금, 바깥 클릭으로 닫기

| 주소 | 용도 |
|---|---|
| `/content-map` | 문서 본체 |
| `/content-map/content_reference_web/fonts/Pretendard-{Regular,Medium,SemiBold,Bold}.woff2` | 폰트 |

| `/content-map/script-thumbnails/FORMAT_HOOK_H####_thumb.jpg` | 대본 100편 썸네일 |
| `/api/content-media/source-{인스타ID}` | 라벨 없는 원본 영상 (7편 사용) |
| `/api/content-media/library-{01..26}` | 분류 라벨을 입힌 분석용 렌더 (팝업에서 재생) |

같은 영상을 두 벌 둔 것이 눈에 띈다. 본문 연출에는 라벨 없는 원본을, 팝업에는 분류 라벨이 박힌 렌더를 쓴다.

## 6. 인터랙션 전체 목록

| 종류 | 위치 | 구현 |
|---|---|---|
| 스크롤 진행 연출 | 장면 9개 | rAF 루프 + 진행도 보간 ([03](03-scroll-engine.md)) |
| 등장 애니메이션 | 일반 섹션 | `IntersectionObserver`로 `.in` 클래스 1회 부여 |
| 구간 반복 재생 | B롤·프로모션 카드 | `timeupdate`에서 끝 지점이면 시작 지점으로 되감기 |
| 소리 토글 | 같은 카드 | 클릭 시 `muted` 전환, 한 번에 하나만 |
| 조합 토글 | 실험실 | `Set` → 정렬해 `-`로 이은 키로 결과 객체 조회 |
| 필터·검색 | 라이브러리, 대본 100 | 배열 `filter` 후 `innerHTML` 통째 재생성 |
| 아코디언 | 대본 100 | 한 번에 하나만 열림, 본문은 열 때 생성 |
| 팝업 | 카드·참조 버튼 전부 | 문서 전체에 클릭 리스너 하나(`data-video`, `data-seek`, `data-pane` …) |
| 패럴랙스 | 카드 썸네일 | 화면 중앙에서의 거리 → CSS 변수 `--py` |
| 스크롤 속도 반응 | 마키 띠 | `Animation.playbackRate`를 스크롤 속도로 조절 |

이벤트 처리는 **위임 한 곳**에 모여 있다. 버튼에 `data-*`만 붙이면 동작하므로 새 버튼을 추가해도 JS를 건드릴 필요가 없다.

## 7. 잘한 점

1. **엔진이 한 가지다.** 장면 9개가 전부 `render(p)` 하나의 형태 — 진행도 0→1을 받아 화면을 그린다. 새 장면 추가 비용이 낮다.
2. **픽셀을 실제로 잰다.** 연결선은 노드의 실제 위치를 읽어 다시 그리고, 폰트 로드 후·리사이즈 때 재측정한다.
3. **확대는 크기로 한다.** 글자가 뭉개지지 않게 `transform: scale` 대신 `font-size`나 SVG 크기 자체를 키운다.
4. **읽는 속도를 설계했다.** 가로 패널은 앞뒤 28% 구간에서 멈춰 있고, 짧은 클립이 몰린 구간은 스크롤 시간을 더 배분한다.
5. **불확실함을 표시한다.** 전사 미검수, 판단 보류, 가상 예시를 화면에 그대로 밝힌다.
6. **접근성 기본기**: `aria-pressed`, `aria-live`, `<dialog>`, 포커스 복귀, 방향키 이동.

## 8. 약점 — 내 것으로 만들 때 고칠 곳

| 문제 | 영향 | 개선 |
|---|---|---|
| 데이터를 HTML에 박음 (1MB+) | 첫 로딩이 무겁고, 내용 고치려면 코드를 열어야 한다 | JSON 분리 후 `fetch`, 팝업 열 때 상세만 불러오기 |
| 썸네일 base64 26장 | 캐시 안 됨, 482KB 낭비 | 파일로 분리 |
| `prefers-reduced-motion` 무시 | 멀미·피로 | 보간 생략 + 전환 제거 (스타터에 반영) |
| 스크롤 59화면 분량 | 끝까지 가기 멀다, 건너뛰기 어렵다 | 장면 길이 축소, 장면 내 단계 점프 |
| 내용이 JS 상수에 흩어짐 | 문구 하나 고치려 해도 위치 찾기 어렵다 | 내용 객체 하나로 모으기 (스타터의 `SITE`) |
| CSS에 덮어쓴 규칙 누적 | 같은 선택자가 3~4번 재정의됨 | 최종값만 남기고 정리 |
| 영상 프록시 무인증 | URL만 알면 누구나 받아 감 | 본인 서비스라면 접근 제한 검토 |
| 매 프레임 `querySelectorAll` | 저사양 기기에서 끊길 수 있음 | 요소 참조를 빌드 시점에 캐시 |
