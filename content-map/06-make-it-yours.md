# 06 · 내 것으로 만들기

## 1. 무엇을 가져가고 무엇을 바꾸나

| 구분 | 항목 | 판단 |
|---|---|---|
| 그대로 써도 되는 것 | 스크롤 장면 구조(`sticky` + rAF + 진행도 보간) | 널리 쓰이는 기법이다 |
| | 연출 아이디어(단어 단위 밝아짐, 트리+카메라, 가로 트랙, 층 분해, 구간 막대) | 기법·아이디어는 누구나 쓸 수 있다. 구현은 스타터처럼 새로 쓴다 |
| | 레이아웃 규칙(여백, 22% 라벨 열, 네 귀퉁이 배치, 큰 글자/작은 라벨 대비) | 규칙이지 표현물이 아니다 |
| | Pretendard | SIL 오픈 폰트 라이선스. 자체 호스팅 가능 |
| | 개념 분류(훅·빌드·보상·CTA, A롤·B롤 등) | 업계 공용 용어 |
| | 데이터 스키마(필드 구성) | 구조만 참고 |
| 바꿔야 하는 것 | 본문 문장, 예시, 가상 사례 | 원 제작자의 글이다. 자기 말로 다시 쓴다 |
| | 개념도·오선지·체스판 같은 도식의 구체적 모양 | 자기 주제에 맞는 비유로 새로 그린다 |
| | 색·모서리 등 겉모습의 조합 | 토큰 4개만 바꿔도 다른 페이지가 된다 |
| | 영상 26편, 대본 100편의 전사·번역 | 인스타그램 원작자들의 것. 링크로만 참조한다 |
| | 전개 분석·요약·판단 이유 | 원 제작자의 분석이다. 자기 관점으로 다시 분석한다 |

원본 사이트가 본인 팀 소유라면 이 표는 해당 없고, 소스를 받아 그대로 고치면 된다.

## 2. 순서

### 1단계 — 내용 뼈대 (연출보다 먼저)

[04-content-framework.md](04-content-framework.md)의 5절을 따라 종이에 먼저 쓴다.

- [ ] 이 페이지가 답하는 질문 한 문장
- [ ] 분류 축 3–5개와 축마다의 구분 질문
- [ ] 축 사이의 관계 트리 (6–10단계)
- [ ] 끝까지 끌고 갈 실제 사례 1개, 가상 예시 1개
- [ ] 마지막에 독자가 할 행동 1개

### 2단계 — 스타터에 채우기

[starter/index.html](starter/index.html)을 브라우저로 그냥 열면 된다(서버·설치 불필요).

- [ ] `SITE.brand`, `SITE.nav`, `SITE.hero`, `SITE.intro` — 제목과 서론 세 문장
- [ ] `SITE.ladder` — 노드(`s` 단계, `x` %, `y` vh), `tree`, 단계별 설명 `notes`
- [ ] `SITE.panels` — 가로 트랙 패널
- [ ] `SITE.curve` — 점 좌표(1600×900 기준)와 라벨
- [ ] `SITE.layers` — 층 이름과 설명
- [ ] `SITE.items`, `SITE.rows` — 사례와 구간 자료
- [ ] `:root` 토큰 — 바탕, 강조색, 여백

장면이 필요 없으면 그 `<section>`을 지우면 된다. `RENDER`에 남은 함수는 호출되지 않을 뿐 문제없다.

### 3단계 — 자료 모으기

[05-data-schema.md](05-data-schema.md) 4절. 표 하나로 시작해서 사례 10개쯤 차면 JSON으로 옮긴다.

### 4단계 — 주제에 맞는 장면 추가

스타터에는 범용 장면 6종만 넣었다. 원본에 있고 스타터에 없는 것:

| 장면 | 필요한 자료 | 난이도 | 참고 |
|---|---|---|---|
| 편집 타임라인 + 모니터 | 한 편의 구간별 시작·끝 초, 영상 파일 | 높음 | [03](03-scroll-engine.md) ⑧ |
| 분석 문장 + 옆 패널 | 용어가 들어간 한 문단, 용어별 축소 그래픽 | 중간 | ②③④ |
| 조합 실험실 | 조합별 결과 문장(3개 토글이면 7가지) | 낮음 | [01](01-teardown.md) 6절 |
| 구간 반복 카드 | 영상 + 구간 초 | 낮음 | ⑧의 되감기 부분 |
| 서론 옆 예시 그림 | 비유에 맞는 SVG | 중간 | — |
| 곡선을 따라가는 카메라 | 스타터 곡선에 확대·이동 추가 | 중간 | ⑦ |

### 5단계 — 다듬기

- [ ] 실제 휴대폰에서 끝까지 스크롤해 본다 (스타터는 390px 폭에서 확인했다)
- [ ] 장면 길이 조절 — 지루하면 `height`를 줄인다. 원본은 총 59화면 분량으로 긴 편이다
- [ ] 영상·이미지는 화면 근처에 올 때만 불러온다(`preload="none"`, `loading="lazy"`)
- [ ] 데이터가 200KB를 넘으면 JSON으로 분리해 `fetch`
- [ ] 공개 여부 결정 — `noindex`는 검색만 막는다. 내부용이면 접근 제한을 따로 건다

## 3. studio3c에 붙이는 방법

| 방법 | 설명 | 맞는 경우 |
|---|---|---|
| **A. 정적 파일로 두기** | 스타터 HTML을 완성해 정적 자산으로 올린다 | 가장 빠름. 이 페이지가 사이트의 나머지와 독립적일 때 |
| **B. 페이지 컴포넌트로 옮기기** | 장면 엔진을 클라이언트 컴포넌트의 훅으로, `SITE`를 데이터 파일로 | 사이트의 헤더·폰트·데이터베이스를 같이 쓸 때 |

B로 갈 때 주의할 점.

- 엔진은 DOM을 직접 만지므로(매 프레임 `style` 대입) 화면에 붙은 뒤에만 돌아야 한다. 렌더 함수가 바꾸는 값은 React 상태로 올리지 않는다 — 프레임마다 리렌더가 일어난다.
- 이 저장소에는 이미 Framer Motion이 있다. 단순 등장 애니메이션(`.rv`)은 그쪽으로 대체하고, 스크롤 진행 장면만 직접 만든 엔진을 쓰는 식으로 나누면 코드가 줄어든다.
- 이 저장소의 `AGENTS.md`가 경고하듯 설치된 Next.js 버전은 관례가 다를 수 있다. 라우트·정적 자산 위치는 `node_modules/next/dist/docs/`에서 확인한 뒤 정한다.

## 4. 스타터가 원본과 다른 점

| 항목 | 원본 | 스타터 |
|---|---|---|
| 내용 위치 | JS 곳곳의 상수 | `SITE` 객체 하나 |
| 사다리 카메라 초점 | 단계별 숫자를 손으로 지정 | 각 단계 노드의 위치에서 자동 계산 |
| 사다리 단계 수 | 10단계 고정 | 노드의 `s` 최댓값에서 자동 |
| 필터 버튼 | HTML에 직접 작성 | 자료의 태그에서 자동 생성 |
| 움직임 줄이기 설정 | 무시 | 보간과 전환을 끈다 |
| 데이터 | 1MB 인라인 | 예시 4건 + 2건 |
| 색·서체 | 차가운 회색 + 주황, Pretendard 자체 호스팅 | 따뜻한 회색 + 파랑, 시스템 서체 대체 |

검증: 1440×900, 390×780 두 크기에서 모든 장면을 스크롤하고 필터·팝업·아코디언을 눌러 보았다.
콘솔 오류 없음, 가로 넘침 없음. 사파리·파이어폭스에서는 확인하지 않았다.
